# ColorTransfer for YMM4

[![License](https://img.shields.io/badge/license-LGPL--3.0-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-ColorTransfer.svg)](https://github.com/routersys/YMM4-ColorTransfer/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、アイテムの色をほかの映像の色の分布へ寄せる映像エフェクトプラグインです。
基準にする映像は、同じシーンの画面、別のシーン、画像や動画のファイル、同じアイテムの中で分岐した映像から選べます。
明るさと色みを別々に扱い、平均だけ、平均と広がり、分布全体の 3 つの合わせ方から選べます。
[YukkuriMovieMaker.Plugin.Community](https://github.com/manju-summoner/YukkuriMovieMaker.Plugin.Community) に提案して取り込まれた「色調転写」を単独のプラグインにしたもので、取り込みの際に manju summoner 氏が加えた修正を含みます。

## 概要

本プラグインは YMM4 の映像エフェクトとして動作します。エフェクトの一覧の「加工」に「色調転写」として表示されます。アイテムの映像と基準にする映像をそれぞれ縮小して読み取り、色の分布を調べます。色の計算は、明るさと色みを分けて扱う色空間である Oklab で行います。調べた分布から、アイテムの色を基準の分布へ移す対応表を色空間の 3 つの軸ごとに 128 段階で作り、ピクセルシェーダーで各画素に適用します。

基準にする映像は、このアイテムがあるシーンの同じ時刻の画面、別のシーン、画像や動画のファイル、同じアイテムの中で「分岐」エフェクトが分けた映像の 4 つから選びます。

設定はアイテムのエフェクトの項目としてプロジェクトに保存します。プラグイン自体の設定ファイルはありません。

画面の表示は日本語のほか、英語、簡体字と繁体字の中国語、韓国語、スペイン語、アラビア語、インドネシア語に対応します。

## 動作要件

| 項目 | 要件 |
|---|---|
| OS | Windows 10 バージョン 2004（ビルド 19041）以降 / Windows 11（64bit） |
| YukkuriMovieMaker4 | 最新版を推奨 |
| ランタイム | .NET 10.0 |

※ 画像と動画のファイルは YMM4 の読み込みプラグインで開くため、YMM4 で開けるファイルがそのまま使えます。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-ColorTransfer/releases/latest) ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4 が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4 を起動し、アイテムの映像エフェクトから「加工」の「色調転写」を追加します。
4. 「参照の取得元」で色を合わせる相手を選びます。既定はタイムラインで、同じシーンの画面に色を合わせます。

## 主な機能

### 1. 参照の取得元

「参照の取得元」で、色を合わせる相手を選びます。

タイムラインは、このアイテムがあるシーンの現在の時刻の画面を基準にします。画面を描くときはアイテム自身を透明にして除くため、自分の色は基準に混ざりません。「再生開始位置」を設定すると、現在の時刻にその分を足した時刻の画面を基準にします。シーンの長さを超えた時刻は最後のフレームで、先頭より前の時刻は先頭で止めます。

シーンは、「参照するシーン」で選んだ別のシーンを基準にします。シーンアイテムと同じく、アイテムの先頭から再生し、シーンの長さで折り返します。「再生開始位置」はアイテムの先頭から数えます。

ファイルは、「ファイル」で選んだ画像や動画を基準にします。動画はアイテムの先頭から再生し、末尾を超えた時刻は最後のフレームで止めます。「再生開始位置」は、選んだファイルの拡張子が動画のときだけ表示します。拡張子が動画のものは動画として、それ以外は画像として先に開き、開けなければもう一方の方法で開きます。選んだファイルはプロジェクトが参照するファイルに含まれるため、プロジェクトの移動とファイルの置き換えの対象になります。

分岐は、同じアイテムで「分岐」エフェクトが先に分けた映像を基準にします。「参照する分岐」に分岐の番号を指定し、0 にすると効果をかけません。自分が置かれている分岐と同じ番号は参照しません。

### 2. 合わせ方

「合わせ方」で、基準の色の分布へどう寄せるかを選びます。計算は Oklab で行い、3 つの軸をそれぞれ独立に対応付けます。

平均は、軸ごとの平均が基準と同じになるように、全体を同じ量だけずらします。

平均と分散は、平均に加えて広がりも合わせます。広がりの倍率は「変化の上限」の逆数から「変化の上限」までに収めます。

ヒストグラムは、分布の形全体を基準に対応付けます。明るさと色みの順序は保ち、対応表の傾きを「変化の上限」の逆数から「変化の上限」までに収めるため、階調が潰れたり極端に引き伸ばされたりしません。

対応表が受け持つ範囲は、アイテムの色の最小と最大に 1 割ずつの余白を足したものです。範囲の外の色は端の傾きのまま延長します。結果が表せる色の範囲を超えたときは、明るさを範囲内に収め、色相を保ったまま鮮やかさを下げて収めます。

### 3. 適用量

「明度の適用量」は明るさの対応表を、「色の適用量」は色みの対応表をどれだけ適用するかです。0% で元のまま、100% で対応表どおりになります。どちらも 0% のときは解析を行わず、映像をそのまま通します。明度の適用量、色の適用量、位置追従の 3 つは、YMM4 のアニメーションの設定で時間に沿って変えられます。

### 4. 位置追従

「位置追従」を上げると、画面の同じ位置にある基準の明暗や色みへ寄せます。基準の画面を縦横 16 ずつの格子に分け、格子ごとの平均と全体の平均との差を、アイテムの各画素が画面に表示される位置に応じて加えます。格子の間は滑らかに補間します。画素の位置は、アイテムの座標、回転、拡大率、反転とカメラの設定から求めます。加える量は「位置追従」の割合に、明るさは「明度の適用量」、色みは「色の適用量」を掛けたものです。

基準がファイルのときは、その画像を画面の大きさに広げたものとして位置を対応させます。参照の取得元が分岐のときは表示されず、使えません。

### 5. 解析

解析は、アイテムの映像と基準の映像を、長辺が「解析の解像度」以下になるまで縮小して読み取ります。縮小は周りの画素を平均する補間で行うため、細い線や動画のノイズで統計が揺れにくくなっています。不透明度が 255 分の 8 に満たない画素は数えず、それ以外の画素は不透明度を重みにします。

読み取った画素と設定のどちらも前のフレームから変わっていないときは解析を省き、前の対応表をそのまま使います。解析は CPU で行い、「解析の解像度」を上げるほど負荷が上がります。

## パラメータ一覧

| 項目 | 既定値 | 内容 |
|---|---|---|
| 参照の取得元 | タイムライン | 色を合わせる相手です。タイムライン、シーン、ファイル、分岐から選びます。 |
| 参照するシーン | 空 | 基準にするシーンです。参照の取得元がシーンのときに表示します。 |
| ファイル | 空 | 基準にする画像か動画です。参照の取得元がファイルのときに表示します。 |
| 再生開始位置 | 0 | 基準の再生位置をずらす量です。シーンとファイルはアイテムの先頭から、タイムラインは現在の時刻から数えます。参照の取得元がタイムラインかシーンのときと、ファイルの拡張子が動画のときに表示します。 |
| 参照する分岐 | 1 | 基準にする分岐の番号です。0 から 1024 までで、0 にすると効果をかけません。参照の取得元が分岐のときに表示します。 |
| 合わせ方 | 平均と分散 | 基準の分布へ寄せる方法です。平均、平均と分散、ヒストグラムから選びます。 |
| 明度の適用量 | 100% | 明るさを基準へ寄せる度合いです。0% から 100% までです。 |
| 色の適用量 | 100% | 色みを基準へ寄せる度合いです。0% から 100% までです。 |
| 位置追従 | 0% | 画面の同じ位置にある基準の明暗や色みへ寄せる度合いです。0% から 100% までで、参照の取得元が分岐のときは表示しません。 |
| 変化の上限 | 4 | 階調を伸縮させる倍率の上限です。1 から 64 までで、合わせ方が平均と分散かヒストグラムのときに表示します。 |
| 解析の解像度 | 128px | 解析のために縮小した後の長辺です。32px から 512px までです。 |

「変化の上限」と「解析の解像度」は「色調転写の詳細」のグループにあります。

## 制限事項

- 基準の画面の中にある別の色調転写は、タイムラインとシーンを参照しません。参照の入れ子は 1 段までです。
- タイムラインとシーンを参照すると、基準の画面を本プラグインが別に描画するため、そのシーンの描画にかかる時間が増えます。
- 分岐では位置追従を使えません。
- 基準がファイルのとき、位置追従はその画像を画面の大きさに広げたものとして位置を対応させます。
- アイテムか基準の映像に、不透明度が 255 分の 8 以上の画素が 1 つも無いときは効果をかけません。
- AviUtl の exo ファイルへの書き出しには対応していません。

## 注意事項

- 同じ名前の効果: YukkuriMovieMaker.Plugin.Community にも同じ色調転写が取り込まれています。それを含む YMM4 では、エフェクトの一覧に同じ名前の効果が 2 つ並びます。本プラグインを使わないときは、プラグインのフォルダーから取り除いてください。
- 参照するファイル: 基準にしたファイルはプロジェクトが参照するファイルに含まれます。プロジェクトを別の場所へ移すときは、YMM4 のファイルの置き換えで移し先を指定できます。
- 更新の確認: アイテムに色調転写を追加するか、色調転写を含むプロジェクトを開いたときに、YMM4 の起動ごとに一度だけ GitHub のリリースを確認し、新しいものがあればメッセージで知らせます。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4 プロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OS の名前とバージョン、.NET のバージョン、CPU のアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4 の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windows のユーザー名、ユーザーフォルダー、AppData のパス、マシン名、ドメイン名、メールアドレス、IPv4 アドレスです。送信元の IP アドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子は YMM4 を起動し直すと別の値になります。

置き換えの対象は上に挙げた文字列だけです。例外のメッセージに基準のファイルのパスが含まれる場合、フォルダーの名前とファイルの名前はそのまま残ります。ファイルを Windows のユーザーフォルダーの外に置いている場合、パスは置き換えを受けずにそのまま残ります。

送信するのは想定していない例外だけです。YMM4 が本プラグインのエフェクトを作るとき、フレームごとに更新するとき、破棄するときと、Direct2D がシェーダーの定数を書き込むときに起きた例外を報告し、その後は YMM4 へそのまま渡します。基準の映像を読み込む途中で YMM4 の読み込みプラグインが出した例外も、本プラグインの更新の中で起きたものとして報告します。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | 基準のファイルが無い、どの読み込みプラグインも開けない、基準のシーンや分岐が無い、基準の映像が透明である |
| 更新の確認の通信の失敗 | GitHub へ接続できない |

送信できなかった報告は YMM4 のユーザーフォルダーへ退避し、次回の起動時に送り直します。送信も再送も非同期に行うため、起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
